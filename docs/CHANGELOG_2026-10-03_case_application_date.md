# 2026-10-03：案件「進捗を更新」で申請日を入力できない問題の修正

## 现象

案件一览的「審査期間」经常显示为 `-`。审查期间以申請日（`applied_at`）为起点计算，申請日为空就无法显示。

## 根因

案件详情的「進捗を更新」对话框里，申請日（原标签「入管局受理日」）的输入栏只在「新进度＝申請済み」或「已经有申請日」时才出现。跳过「申請済み」、直接把进度改为審査中・補正・許可・不許可时，输入栏不出现，后端也只在进入「申請済み」时写入申請日，结果申請日一直为空，只能回到案件一览的编辑对话框补填。

## 修正

- 前端（`CaseDetailPage.vue`，判断逻辑在 `utils/caseProgress.ts`）：
  - 新进度为申請済み・審査中・補正資料待ち・補正資料提出済み・許可・不許可时，都显示「申請日（入管局受理日）」和「受付番号」。已有申請日时照旧始终显示。
  - 申請日未登记时，只有进入「申請済み」才预填今天；其他进度保持为空，不替用户猜日期，并在栏下提示。
  - 申請日为空就保存时弹出确认（可选择「戻って入力する」）；不强制，因为确实可能暂时不知道日期。
  - 未显示的项目不再随请求发送。
- 后端（`status_service.py`）：直接进入審査中・補正・結果等申请之后的进度时，请求里带了申請日・受付番号就一并保存并写入 Timeline；没带就不动，不把变更日当作申請日。已有的申請日不会被空值覆盖。
- 既有案件：打开该案件的「進捗を更新」，当前进度在申请之后的都会出现申請日栏，填入保存即可（进度不变）。不做批量回填。

没有 migration，没有权限变更。

## 验证

- 后端：`apps.cases` 87 项通过（新增 3 项：跳过申請済み时保存申請日并算出审查期间、不猜日期、已有日期不被覆盖）。
- 前端：单元测试 36 项通过（新增 `caseProgress` 3 项）；`npm run build` 通过。
- 浏览器（本地合成数据 QA 库）：受任済み的案件直接改为審査中时出现申請日栏和未填提示；填入后保存，详情和一览都显示审查期间。

## 追加：进度变更不再强制输入理由（2026-10-03）

现象：进度改为「申請準備完了」「申請済み」「完了」等触发警告的情况下，必须填写備考（理由）才能保存；而改为審査中等不触发警告的进度时不需要，行为不一致。

按用户决定，进度变更一律不再强制输入理由：

- 后端 `change_case_status`：去掉「強制変更する場合は備考を入力してください」的限制。備考变为任意，填了仍写入 Timeline。
- 前端「進捗を更新」：去掉对应的前端校验；警告仍然显示，勾选「警告を確認して変更する」（出现警告时自动勾选）后再点一次保存即可。
- 警告本身（必須事項未完了、直接跳到申請済み、未完了事项时完了）保留，只是不再要求写理由。
- **登録状態变更（含归档）不在此范围内**：归档仍需填写理由，这是归档审计的要求，没有改动。

测试：`apps.cases` 87 项通过（原「空備考强制变更返回 400」的断言改为成功）。
