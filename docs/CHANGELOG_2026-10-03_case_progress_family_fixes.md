# 2026-10-03：案件进度更新与家族信息编辑的修正

本文件记录 2026-10-03 的四项修正：申請日无法填写、进度变更强制理由、家族人物信息无法直接修改、案件详情页的大片留白。

## 一、案件「進捗を更新」で申請日を入力できない問題

## 现象

案件一览的「審査期間」经常显示为 `-`。审查期间以申請日（`applied_at`）为起点计算，申請日为空就无法显示。

## 根因

案件详情的「進捗を更新」对话框里，申請日（原标签「入管局受理日」）的输入栏只在「新进度＝申請済み」或「已经有申請日」时才出现。跳过「申請済み」、直接把进度改为審査中・補正・許可・不許可时，输入栏不出现，后端也只在进入「申請済み」时写入申請日，结果申請日一直为空，只能回到案件一览的编辑对话框补填。

## 修正

- 前端（`CaseDetailPage.vue`，判断逻辑在 `utils/caseProgress.ts`）：
  - 新进度为申請済み・審査中・補正資料待ち・補正資料提出済み・許可・不許可时，都显示「申請日（入管局受理日）」和「受付番号」。已有申請日时照旧始终显示。
  - 申請日未登记时，只有进入「申請済み」才预填今天；其他进度保持为空，不替用户猜日期，并在栏下提示。
  - 申請日为空就保存时弹出确认（可选择「戻って入力する」）；不强制，因为确实可能暂时不知道日期。
  - 未显示的项目不再随请求发送。
- 后端（`status_service.py`）：直接进入審査中・補正・結果等申请之后的进度时，请求里带了申請日・受付番号就一并保存并写入 Timeline；没带就不动，不把变更日当作申請日。已有的申請日不会被空值覆盖。
- 既有案件：打开该案件的「進捗を更新」，当前进度在申请之后的都会出现申請日栏，填入保存即可（进度不变）。不做批量回填。

没有 migration，没有权限变更。

## 验证

- 后端：`apps.cases` 87 项通过（新增 3 项：跳过申請済み时保存申請日并算出审查期间、不猜日期、已有日期不被覆盖）。
- 前端：单元测试 36 项通过（新增 `caseProgress` 3 项）；`npm run build` 通过。
- 浏览器（本地合成数据 QA 库）：受任済み的案件直接改为審査中时出现申請日栏和未填提示；填入后保存，详情和一览都显示审查期间。

## 二、进度变更不再强制输入理由

现象：进度改为「申請準備完了」「申請済み」「完了」等触发警告的情况下，必须填写備考（理由）才能保存；而改为審査中等不触发警告的进度时不需要，行为不一致。

按用户决定，进度变更一律不再强制输入理由：

- 后端 `change_case_status`：去掉「強制変更する場合は備考を入力してください」的限制。備考变为任意，填了仍写入 Timeline。
- 前端「進捗を更新」：去掉对应的前端校验；警告仍然显示，勾选「警告を確認して変更する」（出现警告时自动勾选）后再点一次保存即可。
- 警告本身（必須事項未完了、直接跳到申請済み、未完了事项时完了）保留，只是不再要求写理由。
- **登録状態变更（含归档）不在此范围内**：归档仍需填写理由，这是归档审计的要求，没有改动。

测试：`apps.cases` 87 项通过（原「空備考强制变更返回 400」的断言改为成功）。

## 三、在主申请人页面直接修改配偶・子女的人物信息

现象：顾客详情「家族・関係」里点编辑时，已关联人物（`family_customer`）的家族只能改关系、扶养、备注，生日和在留信息等输入栏不出现；而家族卡片上又没有进入该人物页面的入口，实际上无处修改。

修正：

- 前端（`CustomerDetailPage.vue`，差分逻辑在 `utils/familyPerson.ts`）：编辑已关联的家族时显示人物信息栏并预填当前值；保存时只发送用户实际改动的项目（`person`），未改动的不发送，避免把被遮罩显示的证件号按显示值写回。マイナンバー留空表示不变更。按钮文字由「関係を編集」改为「編集」。失败时显示后端返回的字段级原因。把关联对象换成另一位既有顾客时，人物栏照旧隐藏。
- 后端 `PATCH /api/family-members/{id}/`：新增可选只写字段 `person`（只在更新、且关联对象不变时接受；字段白名单为氏名・カナ・生日・性别・国籍・电话・邮箱・邮编・住址・マイナンバー・在留資格・在留カード番号・在留期限・护照号・护照期限）。用 `CustomerSerializer` 做部分更新校验，写审计 `family_person_updated`（证件号・マイナンバー只记录「有变更」，不记录值）。
- 权限（`PartyChildRule._check_person_edit`）：除了原有的「能修改父顾客」之外，被修改的人物必须是操作者本来就能修改的顾客，或者没有其他担当者（含未分配）的进行中案件；否则 403。也就是说不能借家族关联去改写别的担当者正在办理的顾客。只改关系不受影响。
- 旧形式数据（未关联人物的家族行）行为不变：编辑时填写人物信息会新建并关联人物。

没有 migration。

测试：新增 `apps/authentication/tests/test_family_person_edit.py` 6 项（担当者可改生日与在留信息、空マイナンバー不清除、字段级错误、切换关联对象或新建时拒绝、他人担当范围 403/404、不能改写他担当的进行中顾客而李可以）；前端 `familyPerson` 3 项。浏览器（本地合成数据）：编辑配偶时出现并预填人物栏，修改生日和在留期限后保存，请求体只含这两项，卡片显示更新后的值。

## 四、案件详情页「案件関係者・基本情報」与「現在の進捗」之间的大片留白

原因：宽屏下页面是「正文＋右列」两栏（`RecordFormLayout`），但当时只把「案件関係者・基本情報」一张卡片放进了正文栏，与右列（現在の対応・関連レコード・会計・帳票，约 900px 高）并排。右列比这张卡片高得多，所以卡片下方空出一大块，之后的「現在の進捗」等才以整行宽度开始。

修正：把「現在の進捗」「案件進捗・必要資料」「進捗記録」都移进正文栏，与右列并排；右列保持 sticky。只调整了模板中右列和布局结束标签的位置，没有改样式和逻辑。1100px 以下右列照旧排到正文下方。

确认（本地浏览器）：1400px 宽度下两张卡片的间距由约数百 px 恢复为 16px，无横向溢出；1150px 宽度下正文栏约 500px，进度条和表格正常显示。
